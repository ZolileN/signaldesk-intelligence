
SIGNALDESK AFRICA
AI and Machine Learning Architecture
Version: 1.0

1. Design Principle
SignalDesk should not be built around one giant AI model.
The correct architecture is a hybrid intelligence system:
RULES
+
TRADITIONAL ML
+
EMBEDDINGS
+
LLMs
+
KNOWLEDGE GRAPHS
+
TIME-SERIES ANALYSIS
+
HUMAN REVIEW
Each technique should be used where it is strongest.

Who

Where

To whom
With what consequence

announced
a protest
outside Mine X
on Friday
over employment concerns.
Structured event:

9. Event Classification
The classifier should use a hierarchical model.
EVENT
├── POLITICAL
├── ECONOMIC
├── SOCIAL
├── SECURITY
├── INFRASTRUCTURE
├── ENVIRONMENTAL
└── CORPORATE
Then:
SOCIAL
    ↓
PROTEST
    ↓
COMMUNITY PROTEST
This supports flexible future expansion.

10. Event Clustering
Multiple observations may represent the same event.

Social Post C

        ↓
SAME EVENT
Clustering should use:
Semantic Similarity
Time
Geography
Entities
Event Type
Actor Relationships
The output:
5 Observations
    ↓
1 Event

11. Situation Detection
Situation detection identifies when events form a broader condition.
The system looks for:
Temporal Connection
Geographic Connection
Actor Connection
Causal Connection
Topic Connection
Escalation
Example:
Complaint
   +
Meeting
   +
Protest
   +
Road Closure
becomes:
Developing Community Conflict Situation

12. Trajectory Analysis
Trajectory analysis is a combination of:
Time-Series Analysis
+
Event Severity
+
Event Frequency
+
Actor Expansion
+
Geographic Spread
+
Institutional Response
The system should calculate:
Trajectory Score
Conceptually:
Trajectory =
Change in Event Activity
+
Change in Severity
+
Change in Actor Participation
+
Change in Geographic Scope
The output:
Improving
Stable
Escalating
Volatile
Uncertain
The model must provide an explanation.

13. Causal Analysis
Causality should not be inferred solely from correlation.
The system should distinguish:
Observed Cause
Likely Driver
Possible Driver
Correlation
Unknown
The causal graph:
CONDITION
    ↓
GRIEVANCE
    ↓
TRIGGER
    ↓
CATALYST
    ↓
EVENT
    ↓
CONSEQUENCE
The model should combine:
Textual Evidence
Temporal Order
Actor Statements
Historical Patterns
Domain Knowledge

14. Forecasting
Forecasting should produce possible scenarios rather than false certainty.
CURRENT SITUATION
        ↓
HISTORICAL COMPARABLES
        ↓
CURRENT TRAJECTORY
        ↓
ACTOR BEHAVIOUR
        ↓
SCHEDULED EVENTS
        ↓
POSSIBLE NEXT DEVELOPMENTS
Output:
Scenario:
Further protest mobilisation

Likelihood:
Medium

Time Horizon:
7 days

Confidence:
Medium

Evidence:
Recent escalation indicators

The platform should detect:
Emerging Narratives

16. Misinformation and Disinformation Analysis
The system should not simply label information false.
It should analyse:
Claim
    ↓
Evidence
    ↓
Contradiction
    ↓
Source Network
    ↓
Spread
    ↓
Assessment
Possible statuses:
VERIFIED
PARTIALLY VERIFIED
CONTESTED
UNVERIFIED
FALSE
MISLEADING
The platform must distinguish:
Incorrect Information
Intentional Disinformation
Political Narrative
Unverified Rumour
Intent should not be asserted without evidence.

+

18. Recommendation Engine
Recommendations should be generated using:
Situation
+
Customer Role
+
Exposure
+
Severity
+
Time Horizon
The recommendation engine must explain:
Why this action is recommended.
Example:
Recommended action: Review supply-chain contingency plans.
Reason: The situation affects a port used by two suppliers linked to your operational profile.

19. Model Governance
Every AI-generated conclusion should have:
Model Version
Confidence
Evidence
Timestamp
Human Review Status
The system should support:
Model Monitoring
Drift Detection
Evaluation Sets
Human Feedback
Error Analysis

20. Human-in-the-Loop
The platform should use humans where AI uncertainty or risk is high.
AI
 ↓
Confidence
 ↓
Risk Threshold
 ├── High Confidence / Low Risk → Automated
 ├── Medium Confidence → Review Queue
 └── Low Confidence / High Risk → Mandatory Review
This creates a scalable intelligence operation.
